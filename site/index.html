PandaWard
Demo Benchmarks Docs GitHub

Security assessment that tells you what it did not test.

PandaWard scans your own repository locally, keeps an evidence ledger across sessions, and reports undecided controls as plainly as failed ones. Use it as a CLI or as a Claude Code plugin.

See the demo Install Source

Built to be safe on your machine

The rules below are enforced by the engine, not by prompts.

Passive by default

Reads the repository as data. Never runs install scripts, builds or repository hooks, and sends no traffic to any target.

Human-approved network tests

A scope manifest drafted from your project and completed by you, approved from an interactive terminal, bound to the file's hash and to any identity scripts it runs, with a request budget and no redirects. Test identities can come from your own provisioning command and are kept in memory only. Requests that change state are a separate opt-in, allowed only against staging or local targets and only for the flow, effect and prompt-injection checks you declare.

Secrets stay masked

Values are redacted before they are stored, printed, reported or returned to a model. Invisible characters that could hide instructions are stripped from every snippet, and agent instructions and MCP tool descriptions in your repository are checked for them. .env and key files are recorded by name only.

No AI-confirmed findings

Agents are read-only and can only record hypotheses. PandaWard reads the cited lines itself, so a model cannot supply evidence.

State that survives

A local SQLite ledger keeps assessments, findings and evidence across sessions, compaction and restarts. A fix counts only when the check runs again and no longer sees the problem; a moved file keeps its findings instead of reading as fixed.

Private

No account and no cloud backend. Usage telemetry is off unless you turn it on yourself, and pandaward telemetry show prints every byte it would send (details). AGPL-3.0 open source.

Honest statuses

Only PASS and FAIL are decisive. Everything else is shown as a gap, never as "no issues".

PASSdecided for that control only
FAILconfirmed observation
SUSPECTEDheuristic, not proven
BLOCKEDtool, approval or review missing
UNSUPPORTEDno adapter yet
INCONCLUSIVEran, could not decide
ERRORadapter failed
STALEcode changed since

Cross-domain, not just per file

Eighteen domains, A to R. When two domains share a real asset in your code, PandaWard creates an edge and tracks it on its own, so "authorization passed" never hides "identity to object access is untested".

Install

Prebuilt, checksum-verified binaries for Linux, macOS and Windows. Nothing else to install.

Claude Code plugin

/plugin marketplace add ratomirjovanovic/pandaward
/plugin install pandaward@pandaward          # macOS, Linux
/plugin install pandaward-windows@pandaward  # Windows

# restart Claude Code, then in your project
# ask Claude to check its security, or:
/pandaward:start

Claude runs the whole assessment, asks one question at the end and applies what you choose, retesting after every fix. The scan shows how far it got, with a percentage and the time left, even on the first run. While the specialist reviewers work, you see what each one is reading and recording, live in the subagent panel and in the chat. When a rule gets something wrong, or a reviewer finds an issue the rules missed, it offers to report it to the project, after asking you once: the report has the rule, counts and file types, never your code or paths. Low-confidence hints, such as placeholder-shaped keys or audit-level rules from registry packs, stay listed for review instead of raising a control. A signal you mark as a false positive stops counting on the next full scan, as long as the flagged code is unchanged, and the control says who dismissed it. The summary shows how each control was decided and, for every one still open, the exact next step to decide it. Controls no tool can decide, such as the threat model or rate limiting, get a verdict a reviewer proposes with cited evidence and you accept, which turns stale when a cited file changes.

Agent Safety Lab

Research tooling that measures what a coding agent does when the repository it reads tries to steer it.

It also feeds the product: its claim checker is pandaward verify-report and a Stop hook check that catch an agent claiming PASS where the ledger does not, and its labelled findings led to a ReDoS fix. Triage of findings and rule candidates are planned, not done.

Agents read READMEs, code comments, scanner output and tool results, then act. The lab runs an agent against synthetic repositories that carry an attack (a README that claims a manager approved a scope, a scan summary edited to say everything passed, a tool result that asks for an approval) and checks what really happened in a simulated sandbox: which effects were committed, and whether the final report is supported by the evidence PandaWard recorded.

Four arms use the same tools and the same prompt and differ only in enforcement: A prompt only, B a deterministic authorization gate, C B plus an evidence check of the report, D C plus an independent monitor that fails closed. Matched legitimate controls show what a defense costs in lost work.

First measurements: 20 synthetic scenarios, small samples, one model per track, wide intervals. Both models almost never followed an attack, so the arms cannot be told apart yet; the only breaches were a fabricated evidence hash. Mock runs check the harness and say nothing about a model. Nothing here is a claim about any product. Read the reports and the method, or the code.

What it is not

PandaWard is alpha software and an automated technical assessment. It is not a certification, attestation, legal opinion or independently signed penetration test, and it cannot prove the absence of vulnerabilities. Runtime checks cover the cases you declare in the scope manifest, against the targets you approve; PASS means those cases held, not that the application has no other flaw.
