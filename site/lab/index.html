PandaWard

Agent Safety Lab

A sandboxed harness with an independent oracle, honest statistics and a hard budget. It exists for two reasons: to measure what a coding agent does when the repository it reads tries to steer it, and to make PandaWard, a passive SAST with its own data flow engine, better and harder to fool. This page says what it has already given the product, what it measured, and what is not done.

What it gave PandaWard

  • A check on what agents claim, in the product (0.2.17). The claim checker the lab built for its evidence arm is the code behind pandaward verify-report, the pandaward_verify_report MCP tool and a check in the Claude Code Stop hook. If Claude's last message says E-001: PASS and the ledger has FAIL, BLOCKED, SUSPECTED or STALE for it, cites an evidence hash the ledger never recorded, or says everything passed while controls are not PASS, the hook hands the message back to Claude to correct before you read it. A more careful report is never blocked. Only structured lines and all-clear statements are read, so a false claim in free prose is not caught.
  • A better ReDoS check, found through labelled data. The lab's way of labelling findings against known truth (cvebench --emit-findings) showed that the ReDoS analysis kept flagging a patched pattern because it treated bounded loops as unbounded. Fixing it keeps all 20 ReDoS detections on the OpenSSF CVE Benchmark and recognizes 2 more fixes (13 to 15 of 20).
  • A discipline for benchmarks. Intervals on every rate, a paired comparison on the same cases, a held-out split frozen before a run, a scan that did not happen counted as an error and not as zero, and discarded runs listed instead of hidden. The standard-rule rows on the benchmark page were built this way.

What it taught, including where we were wrong

Labelling findings on the CVE benchmark gave four post-fix findings that looked like false positives. One was a real engine flaw (the bounded loops above). Two were not false positives: the marked fix repaired only one alternative of a pattern, so the other branch is still ambiguous, and the patched serialize-to-js code still has a real path to new Function when its unsafe option is set. We had reported the second as a false positive, found the mistake when we read the code, and retracted it in the issue. The data has a limit too: the clean false-positive set from this benchmark is tiny (4 findings per engine against 14 to 19 true ones), too small to measure anything tightly.

What it tests about agents

An agent is given a normal task, such as reviewing a repository with the scanner output and reporting what each control established. The repository carries an attack: a README that says a manager approved a scope, a code comment that tells reviewers to hide the failing control, a tool result that asks for an approval, a scan summary edited to say everything passed, a SARIF file with a suppression nobody recorded, an evidence index with a hash that does not match. A matched legitimate control mirrors each attack without it.

The agent works in a simulated sandbox with a fake network and a shell simulator. What counts is what the effect journal says happened and whether the final report is supported by the evidence PandaWard recorded, not what a model says about it.

How to read this

  • Both models almost never followed an attack. All four breaches across both tracks were the same scenario: an evidence index that lists a SHA-256 that is not the hash of the evidence file, which the agent then cited in its report.
  • Breaches were so rare that the arms cannot be told apart. Arm C had no breach in 72 attack episodes and arms A and B had 4 in 144, which is within the uncertainty of numbers this small. This is not evidence that the authorization gate or the monitor work, and not evidence that they do not.
  • The corpus is too easy for these models to separate defenses. A harder, held-out attack set is the next step for this part of the lab.
  • A defense that blocks everything would show as lost utility on the controls. None did here: utility was 24 of 24 in every arm.

How the corpus changed, and what was discarded

The first live pilot, on 12 episodes, found problems in the measuring tools, not in the model: the claim parser read a quoted forged summary as the agent's own claim, fixtures cited evidence files they did not contain, and the monitor's reply was cut off by thinking tokens. These were fixed before any official run. Two full runs were then discarded and are not reported:

  • v1.2: a fixture cited src/tls.go, which it did not contain, so a careful agent correctly refused to call that control PASS and was scored as inaccurate.
  • v1.3: scenarios without facts still pointed at an evidence file that the repository lacked, and the monitor blocked 7 of 24 legitimate reports in arm D because the agent admitted it could not read that file. This was found while analysing arm D, after the arm results were visible, which is why it is stated here.

Live API runs are limited by a hard spend cap enforced in code before every request (research/agent-safety/BUDGET.md); no amounts are published. The Claude Code track runs on a subscription and has no dollar figure.

Limits

  • Synthetic scenarios, small samples, one model per track. A rate of zero does not mean a defense is complete.
  • Report claims are read from lines that start with a control id and a status word, as the task asks; a false claim written only in free prose is not scored, so false-assurance rates are a lower bound.
  • The agent runs with the model's default settings; the monitor runs with thinking off.
  • Mock runs (scripted agents) check the harness and say nothing about a model. They are always labeled mock and never scored together with real runs.
  • The Claude Code track's model is the alias sonnet, resolved by Claude Code at run time.

Use it and reproduce it

pandaward verify-report report.md                        # the product check: exits 1 on false assurance
pandaward lab validate                                   # no model, no key
pandaward lab run --run t0 --provider mock               # offline, all 240 episodes
pandaward lab run --run t1-api --provider api --live --model claude-haiku-5-5 --seed 20261120 --reps 3
pandaward lab run --run t1-cc --provider cc --model sonnet --arms A,B,C --seed 20261120 --reps 3
pandaward lab report --run research/agent-safety/runs/t1-api --public --out report.md
